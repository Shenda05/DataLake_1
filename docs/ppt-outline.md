# 答辩 PPT 大纲

## 1. 项目背景

- 数据湖平台课程选题背景
- 电商业务的典型痛点：订单、商品、库存数据分散，治理与调度链路割裂

## 2. 项目目标

- 在通用数据湖平台骨架上增量改造成“电商数据湖管理平台”
- 打通接入、资产、分析、治理、调度、监控闭环
- 保证主流程可运行、可演示、可验收

## 3. 技术架构

- 前端：`Vue 3 + Element Plus + Pinia + ECharts`
- 后端：`Spring Boot + JDBC + JWT + H2 / MySQL`
- 文件存储：本地文件系统
- 调度方式：应用内轮询（MVP）

## 4. 核心功能

- 登录与权限控制
- 数据源管理
- 文件导入与数据库表导入
- 数据集与元数据管理
- 查询分析与电商指标可视化
- 数据集成（查询页子标签）
- 数据治理
- 任务调度与日志监控

## 5. 关键实现亮点

- 每个数据集生成独立物理表
- 支持真实 `CSV / JSON / Excel / MYSQL 表` 导入
- 查询分析支持多条件、`AND/OR`、时间范围、分页、排序、SQL 分页
- 数据集成结果可保存为新数据集
- 治理执行生成新数据集，且日志含结构化失败原因
- 日志支持服务端筛选、导出与失败回放

## 6. 演示流程

- 首页指标
- 数据源 / 数据接入
- 数据集管理
- 查询分析与数据集成保存
- 数据治理成功 / 失败
- 任务调度与日志监控

## 7. 测试与结果

- 前端构建通过
- 后端编译通过
- H2 主链路冒烟通过
- MySQL 已完成真实联调与回归
- 浏览器人工检查单已通过

## 8. 团队分工

- 产品与文档
- 前端模块
- 后端模块
- 测试与演示资产

## 9. 当前边界

- 当前任务类型仅 `IMPORT / GOVERNANCE`
- SQL 查询只支持单数据集单表
- 数据集成为查询页子标签能力，不是独立菜单
- 当前调度仍是应用内轮询

## 10. 后续规划

- 更多关系型数据源接入
- 更完整的字段映射与可视化治理参数配置
- Quartz / 独立调度器
- 更丰富的治理算子与审计能力
