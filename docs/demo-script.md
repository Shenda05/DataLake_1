# 答辩演示脚本

## 演示目标

- 用最短路径展示“电商数据接入 -> 数据集管理 -> 查询分析与数据集成 -> 数据治理 -> 任务调度 -> 日志监控”的完整闭环。
- 演示数据、页面顺序和验收口径以 [demo-runbook.md](/Users/xyd/Desktop/DataLake/docs/demo-runbook.md) 为准。

## 建议账号

- 使用管理员账号 `admin / admin123`

## 推荐演示顺序

### 1. 首页开场

- 展示电商仪表盘统计卡片。
- 展示最近任务、最近日志、订单趋势、销售额趋势、热销商品 Top5 和低库存统计。
- 说明平台已经形成“接入、资产、分析、治理、调度、日志”闭环。

### 2. 数据源与数据接入

- 进入“数据源管理”，展示 `FILE / MYSQL` 两类数据源。
- 说明 `MYSQL` 数据源支持“同连接处理策略”：`ALLOW / WARN / REJECT`。
- 进入“电商数据接入”，展示文件导入与数据库表导入。
- 数据库表导入时演示 `Schema / Database` 自动识别下拉，以及切换后表列表自动刷新。

### 3. 数据集管理

- 进入“电商数据集管理”。
- 展示按业务域、来源、状态和关键字筛选。
- 展示元数据、分页预览和导出。

### 4. 查询分析与数据集成

- 进入“电商查询分析”。
- 先执行一个订单条件查询，例如“`order_status = PAID` + `amount >= 200`”。
- 再展示 SQL 分页排序查询。
- 切到“数据集成”子标签，执行 `商品 + 订单` 或 `商品 + 库存` 基础集成。
- 点击“保存为新数据集”，说明集成结果已沉淀为可管理资产。

### 5. 数据治理

- 进入“电商数据治理”。
- 选择一个交易数据集。
- 添加电商算子链，例如 `ORDER_DEDUP + AMOUNT_NORMALIZE + TIME_NORMALIZE + STATUS_NORMALIZE`。
- 先展示一次成功执行，说明会生成新的输出数据集。
- 再展示一次失败执行，说明页面会返回失败步骤、失败原因，并写入结构化日志。

### 6. 任务调度

- 进入“电商任务调度”。
- 展示 `IMPORT / GOVERNANCE` 两类任务，以及电商模板任务入口。
- 立即触发一次任务，观察状态变化。

### 7. 任务与日志监控

- 进入“任务与日志监控”。
- 展示类型、状态、操作人、时间范围筛选。
- 选中一条失败日志，展示详情面板中的输入参数、执行步骤、结构化失败原因。
- 如时间允许，可演示“一键回放”。

### 8. 总结收束

- 返回首页。
- 用最新统计和最新日志说明平台形成了端到端闭环。
- 强调当前版本优先完成课程项目的稳定交付，未把系统写死成只支持单一场景。

## 讲解重点

- 所有页面都连接真实后端接口，不是本地静态 Mock。
- 数据集、查询结果、治理输出都可以沉淀为可管理资产。
- 电商化改造重点体现在数据对象、指标、算子、任务模板和日志表达，而不是仅改标题。
- 当前版本优先保证“能运行、能演示、能验收、能写文档”。
