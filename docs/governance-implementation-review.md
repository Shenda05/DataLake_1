# 数据治理功能当前问题与修改方向

范围：`/governance` 页面、`/api/governance/*` 接口、治理执行落库链路。

## 当前结论

前后端现在能编译通过，后端也已经有“输入数据集 -> 执行算子链 -> 生成新数据集”的基础闭环。主要问题不在能不能跑，而在流程体验、保存/执行状态一致性、字段参数校验和异常数据处理不够稳。

验证情况：

- 前端：`npm.cmd run build` 通过。
- 后端：`mvn -q test` 返回成功；本机 PowerShell/Conda 有一段 PATH 解析警告，但没有阻断 Maven。

## 前端主要问题

1. 治理步骤参数还是手写 JSON。
   - 用户选了数据集之后，页面没有加载该数据集元数据。
   - `field` 只能手填，比如 `order_id`、`amount`，字段不存在时要等后端执行才知道。
   - 修改方向：选择数据集后调用 `listMetadata(datasetId)`，每个步骤的字段参数改成下拉选择。

2. 保存流程和执行流程是割裂的。
   - 点击已保存流程后，页面只是把算子链加载到表单。
   - 再点“执行流程”调用的是 `/governance/execute` 临时执行接口，不会更新 `governance_flow.output_dataset_id`。
   - 所以“最近输出数据集”可能不会变化。
   - 修改方向：新增“执行已保存流程”接口，或执行时带 `flowId` 并回写最近输出。

3. 编辑流程其实没有编辑。
   - `editingFlowId` 只用于高亮和标题。
   - “保存流程”永远调用创建接口，流程名又有唯一约束，编辑原流程时容易重复报错。
   - 修改方向：后端加 `PUT /governance/flows/{flowId}`，前端根据 `editingFlowId` 走创建或更新。

4. 算子选择会混入已停用算子。
   - 页面默认 `includeDisabledOperators = true`，步骤下拉也用同一份 `operators`。
   - 用户可能选到停用算子，执行时后端再失败。
   - 修改方向：算子管理表展示全部，步骤下拉只允许选择 `ENABLED`。

5. 执行结果不能直接查看新数据集。
   - 后端返回了 `outputDatasetId`，但页面只展示文字。
   - 修改方向：执行成功后提供“查看输出数据集”按钮，跳到 `/datasets?datasetId=xxx`。

6. 日志页跳回治理页的 `flowId` 没被处理。
   - `LogsView` 会跳 `/governance?flowId=...`。
   - `GovernanceView` 当前没有读取路由参数并自动选中流程。
   - 修改方向：页面初始化时读取 `route.query.flowId`，加载对应流程。

## 后端主要问题

1. 字段存在性校验不够。
   - 很多算子只读 `row.get(field)`，没有确认字段在元数据中存在。
   - 最危险的是去重：如果字段写错，所有行 key 都可能是 `null`，最后只剩一行。
   - 修改方向：执行前按元数据校验每个算子需要的字段，不存在直接报明确错误。

2. 执行结果没有回写手动执行的流程。
   - `executeSavedFlow` 会更新 `governance_flow.output_dataset_id`，但只有调度任务在用。
   - `/governance/execute` 不关联流程，因此已保存流程列表的最近输出不可靠。
   - 修改方向：新增按 `flowId` 执行的接口，或扩展执行请求体支持 `flowId`。

3. 输出数据集名称有冲突风险。
   - 当前后缀精确到秒，同一秒内重复执行同名流程可能触发 `data_set.dataset_name` 唯一约束。
   - 修改方向：后缀改到毫秒，或失败后自动追加短随机串/序号。

4. 异常数据处理偏硬。
   - 金额标准化、数字比较遇到无法解析的值会直接让整个流程失败。
   - 数据治理一般更适合“记录异常、置空/保留原值、继续执行”，除非用户选择严格模式。
   - 修改方向：给算子加 `onError` 策略，例如 `NULL / KEEP / FAIL`。

5. 长流程配置存储不稳。
   - `governance_flow.operator_chain` 是 `VARCHAR(4000)`。
   - 步骤多、参数多时容易超长。
   - 修改方向：MySQL 用 `TEXT`，H2 也兼容 `CLOB/TEXT`。

6. 执行过程全量拉内存。
   - `fetchAll` 会把输入数据集全部读进内存。
   - 课程项目小数据量可以接受，但真实数据量大时会卡。
   - 修改方向：先保留现状，后面再做分页/流式处理。

## 建议修改顺序

1. 先改前端字段选择：选择数据集后加载元数据，步骤里用字段下拉替代手写 `field`。
2. 后端补字段校验，避免字段写错导致静默生成错误数据。
3. 加流程更新接口，修复“编辑流程其实是新增”的问题。
4. 加按已保存流程执行接口，并回写最近输出数据集。
5. 执行成功后前端跳转查看输出数据集。
6. 再处理异常数据策略、operator_chain 字段类型、执行性能这些增强项。
